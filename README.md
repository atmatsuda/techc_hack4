コンセプトと解決する課題背景・課題： Webデザイン学習初学者が抱える「実践的なお題の不足」と「制作物に対する客観的評価の欠如」。解決策：動的お題生成エンジン： ターゲット属性や業界に特化した課題をワンタップで無限生成。Figma URL提出 ＋ 模擬AI自動採点： デザインのURLを送信するだけで、リアルタイムでカテゴリ別フィードバックを出力。再提出による成長の可視化： によるレスポンシブ構成。外部連携： Figma OAuth 2.0認可 ＆ Figma REST API（v1/files/{file_key}）によるサムネイル画像全自動取得パイプライン。2.3 セキュリティ多重防御設計SQLインジェクション対策： PDOプリペアドステートメント（静的プレースホルダー PDO::ATTR_EMULATE_PREPARES => false）の徹底。XSS（クロスサイトスクリプティング）対策： 出力部における独自エスケープ関数 h()（htmlspecialchars）の100%適用。CSRF対策 / セッション管理： 暗号学的に安全なワンタイムトークン生成・検証（hash_equals）および session_regenerate_id(true) によるセッションハイジャック防止。3. 7. 想定質疑応答 21選（Q&A集）【プロダクト・企画について】Q1. 外部AI API（OpenAI等）を直接使わなかった理由は何ですか？A. 開発期間が約2週間と限られる中で、応答遅延やエラー対応コストを考慮しました。ハッカソンにおいて「確実に動作する完成度」を最優先し、バックエンドのロジックで再現性のある模擬AI評価エンジンを構築する「要件の引き算」を行いました。Q2. なぜ画像アップロードではなく「Figma URL」の提出形式にしたのですか？A. 実務で標準的なFigmaの運用に合わせると同時に、サーバー側での画像保存容量やセキュリティリスクを抑え、Figma API経由でサムネイルを軽量に自動取得するためです。Q3. 「無限お題生成」はどのように動いていますか？A. バックエンドでターゲット・業界に特化したお題データを保持し、動的に抽出しています。将来的にGenerative AI APIへスムーズに差し替えられる拡張可能な設計です。Q4. 審査員ペルソナ（鬼軍曹、エンジェル、ビジネス）を分けた意図は？A. 「厳しく指導されたい」「褒めて伸びたい」など、学習者のその日の気分や成長フェーズに合わせて選べるようにするためです。Q5. ターゲットユーザーは誰ですか？A. XAMPP環境（Apache + MySQL + PHP）を使用しました。【セキュリティについて】Q12. SQLインジェクション対策は？A. PDOの静的プレースホルダー（PDO::ATTR_EMULATE_PREPARES => false）を用いたプリペアドステートメントを全DB操作で徹底しています。Q13.
