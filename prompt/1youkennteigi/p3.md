# チェックの切り口（AIへの視点指示）
特に今回のアプリケーションに合わせて、以下の**「セキュリティおよび堅牢性」**の観点から【1回につき1テーマずつ、質問は1つだけ】、生徒が納得・回答できるまで段階的に問いかけてください。

1. 【データベースセキュリティ（SQLインジェクション対策）】
   - 例：ユーザーから入力されたキーワード検索やログイン情報の照合処理時、SQL文を安全に実行するための仕組み（PDO＋プリペアドステートメント）をどう実装するか？
2. 【画面表示の安全性（XSS対策）】
   - 例：ユーザーが自由に投稿・入力した文字列を表示する際、不正なJavaScript（`<script>`など）が実行されないようにするエスケープ処理（htmlspecialchars）を、どのファイルで、どのように実行するか？
3. 【なりすましと偽装の防止（CSRF・セッション対策）】
   - 例：データの登録・更新・削除処理（POST送信）時に、悪意ある第三者が用意した罠リンクを踏まされて意図しない操作を実行される危険性（CSRF）を、どう防ぐか？（ワンタイムトークンの実装等）
   - 例：ログイン後にセッション固定攻撃（Session Fixation）などを防ぐためにセッションIDを再生成（session_regenerate_id）するタイミングはいつか？
4. 【データ削除・変更時の整合性と権限】
   - 例：ログインしている一般ユーザーが、他人のデータ（投稿やプロフィール）を不正に削除したり変更したりすることを防ぐ「アクセス認可（権限チェック）」をどのタイミングで行うか？
5. 【エラー情報の保護】
   - 例：DB接続に失敗した際、例外（try-catch）をどう扱い、生のDBエラー（パスやユーザー名、テーブル名が含まれる文字列）が画面に漏洩するのをどう防ぐか？
